# MADILOG — симуляция системы идентификации морских дронов

Демо-стенд: **генератор модулей → API → сервер (треки, реестр в БД, проверка подписи) → интерфейс оператора**.
Всё работает на одном ноутбуке без железа. Это симуляция: цифры дальности берутся из модели канала
с допущениями (`sim/channel.py`), на слайдах их нужно подписывать «расчёт / моделирование».

## Быстрый старт
```
pip install -r requirements.txt
python run_demo.py            # сервер + генератор + браузер (http://127.0.0.1:8000)
python run_demo.py spoof      # сценарии: own | unknown | silent | spoof | mixed
python run_demo.py mixed --range-only   # модули без угла: позиция по дальностям с 3 станций
python -m sim.plot_channel    # графики модели канала -> sim/out/channel.png
python -m pytest              # 11 тестов
```
Вручную: `uvicorn server.app:app --port 8000` и в другом окне `python -m sim.generator --scenario mixed`.

## Что делает система
1. **Модуль** (буй или корабль, на котором закреплён модуль) шлёт 150 кГц скан-импульс, затем запрос.
   Модуль считает **измерения**: дальность `R = c·t/2` и, если есть решётка, азимут. Координаты он не считает.
2. **Аппарат** отвечает кадром 17 байт: ID, счётчик, глубина, подпись HMAC (4 байта), CRC16 (`sim/packet.py`).
3. Модуль декодирует кадр, проверяет CRC и шлёт на сервер `POST /api/v1/detections`.
4. **Сервер** (`server/engine.py`):
   - переводит измерения в координаты (полярные или трилатерация по ≥2–3 станциям);
   - склеивает «эхо» и «ответ с ID», если они рядом (окно 30 м);
   - проверяет ID по реестру (SQLite), подпись и счётчик;
   - выдаёт статус: **свой / чужой (нет в реестре) / нет допуска / подмена ID / не подтверждено**.
5. **Интерфейс** (`ui/index.html`) показывает карту, таблицу объектов, реестр (можно добавлять), журнал.

## API
`POST /api/v1/detections`
```json
{"module_id":"BUOY-01","pose":{"lat":60.0,"lon":28.99,"heading_deg":0},"sound_speed_mps":1500,
 "detections":[
  {"kind":"echo","range_m":80.2,"az_deg":10.0,"snr_db":6},
  {"kind":"transponder","range_m":420.5,"az_deg":45.0,"id":"MD-0427","counter":1234,"mac":"a1b2c3d4","crc_ok":true,"depth_m":38}]}
```
`az_deg` необязателен. Остальное: `GET /api/v1/state`, `GET|POST /api/v1/registry`, `POST /api/v1/reset`.
Документация Swagger: `http://127.0.0.1:8000/docs`.
Реальный модуль подключается так же: вместо генератора шлёт тот же JSON (MQTT/HTTP).

## Что показывает симуляция честно
- Ответ с ID слышен на ~1,3 км (35 кГц), а эхо на 150 кГц обнаруживает объект всего на ~150 м (модель, допущения).
  Поэтому «молчащий» объект виден только рядом со станцией; это аргумент в пользу идентификации ответом
  и вариант улучшения (понизить частоту скана: `--scan-khz 40` -> ~230 м, но хуже разрешение).
- Без угловой решётки молчащий объект не локализуется (эхо без угла нельзя однозначно сопоставить между станциями).
- С двумя станциями позиция неоднозначна (зеркальное решение), нужна третья или история трека.
- Подмена ID и повтор старого пакета ловятся подписью и счётчиком. Ключи в демо шаблонные.

- Обёртка счётчика (16 бит), ротация ключей, шифрование.
- Подключение реальных плат (STM32) вместо генератора.
