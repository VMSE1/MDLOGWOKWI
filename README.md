# MADILOG: модуль «свой — чужой» для морских дронов на STM32 (Wokwi)

Плата STM32 работает как ответчик подводного дрона: раз в секунду она отправляет кадр со своим ID, счётчиком и криптографической подписью. Мост на ноутбуке пересылает кадр на сервер. Сервер сверяет ID с реестром и показывает оператору статус: **свой**, **чужой**, **подмена ID**.

Проект команды MADILOG (МАДИ) для Международных транспортных проектных соревнований РУТ МИИТ, проблема № 02 «Система идентификации морских дронов». Это **макет, протестированный в моделируемых сценариях**, а не готовое устройство.

```
[STM32 Nucleo / Wokwi] --FRAME по UART/USB--> [tools/serial_bridge.py] --HTTP JSON--> [сервер: FastAPI + SQLite + карта]
```

## Быстрый старт

Нужны Python 3.11+ и (для Wokwi) VS Code с расширением Wokwi Simulator.

```bash
pip install -r simulation/requirements.txt pyserial

# 1. сервер с интерфейсом оператора
cd simulation && uvicorn server.app:app --port 8000      # http://127.0.0.1:8000

# 2. плата: открой папку firmware_wokwi в VS Code, F1 -> "Wokwi: Start Simulator"

# 3. мост плата -> сервер (из корня репозитория)
python tools/serial_bridge.py --port rfc2217://localhost:4000
```

На карте появится MD-0427 со статусом «СВОЙ». Зажми красную кнопку в Wokwi, и статус станет «ПОДМЕНА ID».

Без платы, только симуляция всей системы: `cd simulation && python run_demo.py mixed`.

**Подробная инструкция** (что нажимать, распиновка, формат кадра, подключение по USB / статическому IP / Wi-Fi, план сборки в железе): [docs/ПЛАТА_и_подключение.md](docs/ПЛАТА_и_подключение.md).

## Структура

| Папка | Что внутри |
|---|---|
| `firmware_wokwi/` | Прошивка для Nucleo-C031C6: кадр 17 байт, CRC16, HMAC-SHA256, кнопка «подмена», светодиод. Готовая сборка лежит в `build/` |
| `tools/serial_bridge.py` | Мост: читает строки `FRAME,<hex>,<м>` из порта (USB, Wokwi, stdin) и шлёт их в API |
| `simulation/` | Сервер (FastAPI), реестр (SQLite), интерфейс оператора, генератор сценариев, модель канала, тесты |
| `mockups/` | Макет стенда и анимация алгоритма (HTML) |
| `docs/` | Документация по плате и подключению |

## Проверки

```bash
cd firmware_wokwi
make            # сборка (нужен arm-none-eabi-gcc)
make test       # кадр и подпись на ПК совпадают с Python: d3e0c212, a501000001ab000a018100d3e0c2125e28
make emu        # прогон прошивки в эмуляторе ядра Cortex-M0+ (pip install unicorn pyelftools)

cd ../simulation
python -m pytest   # 11 тестов сервера и симулятора
```

Что проверено: сборка, `make test`, `make emu`, 11 тестов и цепочка «вывод прошивки → мост → сервер» (статусы «СВОЙ», «ПОДМЕНА ID», битый CRC отброшен).
Что **не** проверено: запуск внутри Wokwi и на настоящей плате.

## Честные ограничения

- Дальность в прошивке имитируется (20–300 м). Все дальности в симуляции получены из модели канала с допущениями (`simulation/sim/channel.py`), а не измерены.
- Акустической части (пьезоэлементы 25–150 кГц, усилители) в макете нет.
- У платы нет угла. При одной станции мост подставляет условный азимут (`--az`), иначе сервер не может поставить точку на карте.
- Ключи (`key-0427` и др.) демонстрационные и лежат в открытом виде.

## Что дальше

- Приём сырого кадра в API (`POST` с hex и дальностью), чтобы ESP32 или модем могли слать кадры напрямую.
- Порт `main.c` на Nucleo-G474RE (`frame.c` переносится без изменений).
- Потенциометр или ультразвуковой дальномер вместо имитации дальности.
